# My Dictionary Security Policy

## Reporting a vulnerability

Do not publish exploit details, credentials, private notes, backup files, or provider secrets in a public GitHub issue.

GitHub private vulnerability reporting is enabled for this repository. Use the repository Security tab and the private vulnerability reporting form to submit a report.

If private reporting is not available, contact the repository owner through a private channel and provide only the minimum information needed to reproduce the issue. Do not use a public issue for an active vulnerability.

## Include

- the affected URL, route, or release commit;
- a short description of the impact;
- reproducible steps or a minimal proof of concept;
- the expected and observed behavior;
- whether any user data or secret could be exposed.

Please allow time for confirmation and remediation before public disclosure.

## Keep secrets out of reports

Never include API keys, metrics tokens, passwords, access tokens, private backup files, or personal notes. Rotate a secret immediately if it was exposed.

## Scope

Reports may cover the My Dictionary web application, dictionary proxy, deployment configuration, and release artifacts. Third-party provider outages, provider content quality, and vulnerabilities in dependencies should be identified clearly so they can be routed to the correct owner.
